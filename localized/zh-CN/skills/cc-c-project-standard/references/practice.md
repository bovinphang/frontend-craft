# C 工程规范

## 关键检查

1. 读取现有 C 标准、编译选项、构建系统和导出 ABI，保留符号可见性、调用约定及错误码。

2. 每个资源接口说明分配方、拥有方、借用期限、转移时点和配对释放函数；失败时初始化输出值。

3. 部分初始化采用明确 cleanup 路径，仅释放已获取资源并防止二次释放；不把 C++ 资源机制强加给 C。

4. 内存访问/分配前检查长度、整数溢出、对齐和有无符号转换；外部畸形输入用可恢复错误处理，不使用 assert 代替。

5. 逐阶段注入分配与解析失败，测试成功转移及每个提前返回；审查跨 FFI/运行库的所有权。

6. 使用现有构建和可用编译诊断/sanitizer，说明实际覆盖的平台与失败路径；静态分析不能证明没有所有未定义行为。

## 边界与案例

适用场景：
- 审查 C 分配和释放契约
- 保持 C ABI 修复失败清理
- 组织已有 C 库头文件和实现
- 测试 C 分配失败与非法输入

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
