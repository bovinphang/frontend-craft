# 保持行为的重构

重构改变内部组织并保持可观察契约，使用 GREEN → REFACTOR → GREEN，不为结构变换制造失败的行为需求。

1. 区分结构调整、新行为、缺陷修复和依赖迁移；行为变化进入独立流程。
2. 阅读实现、调用方、导出、注册、持久化与测试；改动前定义结果、错误、副作用及顺序、状态变换、公共名称和协议。
3. 建立绿色基线，或记录已有失败。关键行为缺少覆盖时补充描述当前行为的特征测试，可以从绿色开始。
4. 诊断结构证据并排除误判。行数或复杂度指标本身不足以证明应当重写；优先选择最小安全、可回退的变换。
5. 规划前置步骤；每步记录目标、结构意图、手法、风险、预计文件/函数、公共 API/行为变化（纯重构为零）、验证和回退边界。
6. 一次只改一个主要结构问题，立即运行最近的有效校验并检查差异；实际范围超出预算时停止并重新评估。
7. 新回归使当前步骤失效：只撤回当前结构步骤，验证前一基线，再缩小或调整顺序；不撤销无关用户改动，不跨无关模块扩散修复。
8. 按受影响契约扩展验证：本地/静态、单元/集成、完整 lint/类型/测试、构建和相关专项。使用现有工具，不强制引入框架。

风险依上下文判断：SAFE 为证据充分的局部私有变换，CAUTION 为跨模块/共享状态/生命周期变换，DANGER 为公共 API、schema、持久化、鉴权、权限、协议或架构级变化。手法名称不自动决定安全等级。

给出证明结论：PASS 表示相关行为充分覆盖且校验通过；PARTIAL 表示已执行检查通过但仍有重要覆盖缺口；NOT PROVEN 表示证据或环境不足以证明行为保持。附实际命令、回退决定和剩余风险。
