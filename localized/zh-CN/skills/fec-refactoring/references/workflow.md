# 重构执行工作流

## 状态机

```text
分类请求
→ 发现上下文
→ 建立基线
→ 诊断结构证据
→ 建立安全网
→ 构建有序计划
→ 风险检查
→ 执行一个重构步骤
→ 立即验证
   通过：检查 diff 后进入下一步
   失败：回滚当前步骤，确认基线，再缩小或重排
→ 最终验证
→ 报告
```

## 上下文发现

按需读取 `package.json`、工作区清单、TypeScript/ESLint 配置、测试脚本、受影响模块和调用点、barrel 导出、路由和注册点、store/持久化边界、生命周期敏感逻辑、异步副作用以及当前 Git diff。

## 基线处理

基线为绿时，当前步骤之后新出现的相关失败应优先视为该步骤可能引入的回归。基线已经为红时，要记录精确失败，不能没有比较证据就把后续失败归因于重构；安全证明不足时不要继续高风险变换。

## 单步计划契约

```text
目标：
手法：
意图：
前置条件：
风险：SAFE | CAUTION | DANGER
预期文件数：
预期函数/组件数：
预期公开 API 变化：0
预期行为变化：0
验证：
回滚边界：
```

## 单步失败协议

修改前为绿、当前步骤后变红时：停止；只回滚当前步骤；重跑相关检查确认基线恢复；判断失败源于行为、身份、生命周期、顺序、类型还是依赖假设；缩小步骤或增加前置重构；证据恢复后才能重试。

不要为了“修绿”把改动扩散到不相关模块。

## 最终验证

按由窄到宽的顺序运行：最近的语法/类型检查、目标单元或组件测试、受影响集成测试、lint + 全量 typecheck、更广测试、构建，以及实际受影响时的 SSR、E2E、视觉、无障碍、性能等门禁。

## 证明结论

- **PASS**：相关可观察契约覆盖充分，要求的检查全部通过。
- **PARTIAL**：已执行检查通过，但重要行为覆盖仍不完整。
- **NOT PROVEN**：依赖、环境、基线或安全网不足，无法可信证明行为保持。
