# 文档事实同步

从实现事实同步公共文档，不把期望设计写成既有能力。

1. 明确技术栈、文档入口和本次范围，覆盖根 README、嵌套包/应用/Runtime README 和部署指南；排除依赖、构建产物和第三方目录。
2. 收集权威事实：清单和锁文件、配置、环境变量示例、命令、schema、公共 API、测试、CI、构建与部署文件。使用实际技术栈的来源，不强制某一种语言的项目清单。
3. 对照命令、环境变量名、路径、版本、API 行为、能力、安装和部署说明。只写稳定公共事实，不将提案和实验设计描述为已支持行为。
4. 检查全部已有语言入口。公共标识、命令、版本范围、支持矩阵、报告路径和示例必须一致；文案遵循现有翻译约定，明确需要人工复核的内容。
5. 同步相关 README/docs/ADR/changelog 和用户可见元数据。ADR 记录背景、决定、备选、影响、验证和回退线索，不写成完整评审报告。
6. 执行项目已有一致性、相关类型/测试/构建/打包检查和旧引用搜索。记录每份已查文档、事实源、已同步语言、不需修改的入口和未决问题。

不虚构命令或环境变量，不越界修改用户私有文档，不用内部实现细节淹没 README。文案编辑成功不等于事实一致性已经验证。
