# Rust 异步生命周期

## 关键检查

1. 识别运行时/版本、挂起点、资源拥有者和取消边界；依据实际 future 文档判断取消安全。

2. 区分取消等待者与停止操作；超时写入可能已改变流，必须定义部分进展后的恢复。

3. 管理任务句柄，限制队列和在途任务，传播错误；无限脱离任务不是停机方案。

4. 不可避免阻塞操作放入适当且有界的边界，取消仍须尊重底层操作生命周期。

5. 先停止接单，再排空/取消所拥有任务，定义期限与收尾完成条件；select 不提供业务幂等。

6. 用可控调度、短写、取消和背压测试；报告实际运行的运行时及错误路径。

## 边界与案例

适用场景：
- 修复 Tokio select 取消导致的部分写入
- 限制 Rust spawn 数量并管理 JoinHandle
- 设计 Rust 异步停机和取消
- 隔离异步执行器中的阻塞 I/O

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
