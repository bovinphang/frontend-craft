# 原生内存与 FFI 安全

## 关键检查

1. 保留可复现输入、分配/释放栈、平台/运行库身份及并发销毁时序。

2. 逐边界说明拥有者、别名、借用期限和分配器配对，分配运行库必须有受支持的对应释放路径。

3. C 使用明确所有权转移和部分清理路径；C++ 使用适当 RAII/自定义删除器，同时保留借用语义。

4. 异常和不支持的实现类型留在 ABI 边界内；访问前检查缓冲区长度、溢出及对象生命周期。

5. 覆盖失败注入、重复关闭、卸载后回调和并发销毁；只置空一个指针不能消除悬挂别名。

6. 按适用条件分别运行地址/未定义行为/线程诊断及回归，记录不可用工具和覆盖限制。

## 边界与案例

适用场景：
- 诊断 C/C++ FFI 边界的 use-after-free
- 配对动态库之间的分配和释放
- 测试部分初始化及重复清理
- 保留 sanitizer 复现销毁竞态

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
