# 测试驱动开发

新增行为和改变行为的缺陷修复使用 RED → GREEN → REFACTOR，测试描述可观察契约，不锁死内部实现结构。

1. 确定一个行为：输入、输出/错误、状态变换或外部可观察副作用。沿用项目现有工具，选择最接近风险且有效的测试层。
2. 先写能区分缺失或错误行为的最小测试并运行，观察预期行为导致的失败，不将语法、导入或环境错误当成红灯。缺陷测试必须在原缺陷存在时失败。
3. 只实现足以通过测试的最少代码。红灯阶段不重构，不增加无关功能。
4. 重跑测试及相关周边测试，再在保持绿色的前提下整理命名和结构；新需求进入下一轮。
5. 报告实际红绿命令、覆盖行为和未测边界，不根据差异或未执行的测试推断成功。

纯结构重构使用另一条契约：以已有测试或特征覆盖建立当前行为，保持 GREEN → REFACTOR → GREEN，不为流程形式制造失败。

逻辑就近测试；真实边界用集成测试，需要完整旅程时才用端到端测试。不默认上 E2E，不断言脆弱私有状态，不仅为 TDD 引入新框架。项目缺少测试设施时先说明最小搭建方案，并在获得决定后引入；按实际技术栈选择工具，不要求前端测试工具。
