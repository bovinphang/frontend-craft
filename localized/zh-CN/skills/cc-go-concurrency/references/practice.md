# Go 并发生命周期

## 关键检查

1. 列出 goroutine 创建方、停止信号、阻塞操作和等待完成方；请求返回不能证明 worker 已退出。

2. 在阻塞点响应 context 并限制并发，接收方退出时发送方必须能结束。

3. 明确 channel 关闭归属，多发送方需协调完成后再关闭，不用 recover 掩盖发送/关闭竞争。

4. 依据共享状态不变量与 happens-before 需求选择同步方式，锁、channel 和原子变量职责不同。

5. 用屏障或可控事件覆盖取消、消费者提前退出、队列饱和与并发停机。

6. 运行可用 race 测试并检查重复请求后的任务/栈证据；有限测试通过不能证明所有交错安全。

## 边界与案例

适用场景：
- 终止阻塞在 channel 发送的 Go worker
- 明确共享 Go channel 的关闭方
- 限制 goroutine 并传播请求取消
- 复现和测试 Go 数据竞争

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。
