# C++ 工程规范

## 关键检查

1. 选择特性前读取实际 C++ 标准、标准库、编译器矩阵、构建 preset 和导出 ABI。

2. 使用合适 RAII owner 表达所有权，借用指针保持明确借用；不要把外部拥有的裸指针擅自包成共享拥有。

3. 说明异常保证并处理部分构造的资源释放；在明确边界捕获并准确转换失败，保持析构安全。

4. 跨 DLL/FFI 时分配与释放配对，避免异常和不稳定实现类型穿越不支持的 ABI 契约。

5. 审查析构顺序、回调生命周期及卸载同步，测试竞争销毁和错误路径，而不只测成功构造。

6. 在声明平台验证现有构建和可用诊断，缺工具明确报告；编译成功不能证明竞态或生命周期安全。

## 边界与案例

适用场景：
- 审查 C++ RAII 和异常安全
- 保持插件 ABI 并明确所有权
- 整理头文件与模板依赖边界
- 测试 C++ 析构及部分构造

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
