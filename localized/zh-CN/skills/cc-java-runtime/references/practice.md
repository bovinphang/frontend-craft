# Java 运行时诊断

## 关键检查

1. 对齐同一时间窗的吞吐、延迟分位、错误、排队、CPU、分配/GC 及下游耗时。

2. 按许可采集有界 JFR 和重复线程样本，选择能区分竞争解释的观察项。

3. 扩容前检查队列上限、拒绝策略、请求期限、池归属和阻塞调用。

4. 一次调整一个有证据的约束，并在等价负载下对照；增堆或增线程可能把压力转移到下游。

5. 定义错误、延迟与资源饱和的回滚阈值，在受控环境演练过载和恢复。

6. 将观察事实、假设和未测效果分开报告，不凭单次本地计时声明根因或 p99 改善。

## 边界与案例

适用场景：
- 诊断 Java p99 和线程池队列上涨
- 为 JVM 事件采集有界 JFR 与线程样本
- 以基线对照 JVM 堆或线程池调整
- 排查 Java 阻塞竞争和下游等待

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
