# Python 工程规范

## 关键检查

1. 读取 pyproject、锁/环境约定、支持的 Python 版本及包布局；不混入新安装器或隐式替换环境。

2. 纯领域计算独立于传输/数据库客户端，外部资源在应用启动或明确工厂创建，不在导入时创建。

3. 遵循类型约定并明确数据边界，外部输入进入核心计算前校验，保留错误原因而非广泛静默捕获。

4. 定义文件、会话和客户端由谁关闭，使用合适的上下文管理器，异步生命周期交给对应专项。

5. 保留现有测试，覆盖非法输入、金额/舍入边界、部分失败和导入安全；fake 不证明数据库事务。

6. 在已有环境中运行配置的 Ruff、类型与测试命令；缺模块就报告缺失，不自动安装或虚称通过。

## 边界与案例

适用场景：
- 遵循 pyproject 组织 Python 领域包
- 移除导入时连接数据库的副作用
- 审查 Python 类型和依赖边界
- 使用现有 Ruff mypy pytest 配置

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
