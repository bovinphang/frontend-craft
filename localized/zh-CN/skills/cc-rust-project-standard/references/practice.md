# Rust 工程规范

## 关键检查

1. 先读 Cargo.toml、workspace 成员、edition、MSRV 与现有 alias；在所属 crate 内改动，不顺手升级整个工作区。

2. 在接口边界明确所有权；调用方持有生命周期时优先借用，共享所有权必须有真实共享生命周期需求。

3. 遵循仓库错误分类与 Result 传播，保留原因链，在应用边界映射，不在公共诊断中暴露敏感信息。

4. 隔离领域逻辑、持久化与传输，检查锁守卫生命周期，避免持有阻塞锁跨越挂起点。

5. 同时测试畸形输入、部分持久化、回滚和所有权转移；使用临时资源与确定性失败注入。

6. 使用现有锁与工具链运行可用的 fmt 检查、clippy 和定向 Cargo 测试；缺少工具链必须记为未验证。

## 边界与案例

适用场景：
- 规划现有 Cargo workspace 的 crate 边界
- 审查 Rust 公共接口所有权和 Result 边界
- 保持现有 edition 增加存储模块
- 为 Rust 库选择工程质量检查

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
