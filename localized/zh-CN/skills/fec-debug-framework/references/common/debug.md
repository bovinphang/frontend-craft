# 证据驱动诊断

通过五步流程确认根因后再修复。

1. **分类：** 描述可观察故障、影响、版本、环境和最小复现，以项目证据确定相关子系统；跨层问题从表面症状逐层追踪。
2. **收集：** 使用最小失败命令或操作复现，收集必要日志、trace、状态、配置和近期变更；隐藏凭证和敏感载荷。领域适配层提供技术栈专属诊断入口。
3. **假设：** 最多保留三个按证据排序的假设，每个说明“X 导致 Y，可由 Z 证实或证伪”；不把症状或猜测性修复当作根因。
4. **验证：** 一次改变一个变量，从最强假设开始，记录已证实/已证伪/待确认。全部失败则重新收集证据；同一假设连续三次失败时报告阻塞，不反复重试。
5. **修复与校验：** 实施已确认根因的最小修复，保留回归复现，先运行受影响校验再扩大。已有失败单独记录，不关闭测试或削弱校验来宣称成功。

依赖或环境故障先对比精确工具链、依赖版本、锁文件和本地/CI 差异，再决定是否升级。迁移与普通缺陷修复分开；没有证据时不先加重试、调超时或吞掉异常。

交付 `reports/debug-YYYY-MM-DD-HHmmss.md`，包含症状与复现、证据、假设/结果表、根因、修改文件和行为、实际验证、剩余风险及下一步。没有观察到结果时不宣称修复或测试全绿。
