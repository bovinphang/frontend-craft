# Java 工程规范

## 关键检查

1. 读取声明的 JDK、构建文件、wrapper 和包分层，保持当前语言级别与依赖平台。

2. 将公共模块契约与实现细节分离；Java 库、CLI 和 Swing/JavaFX 桌面模块各自保持现有依赖方向。

3. 明确文件、线程池和客户端的创建与关闭方；实际使用 Swing/JavaFX 时，将阻塞工作与 UI 线程区分。

4. 保留异常原因并遵循仓库约定，在边界转换领域错误，不使用 catch-all 吞错后返回成功。

5. 测试公共行为、非法输入、重复调用、异常原因和资源关闭；按照既有应用边界验证失败副作用。

6. 使用已有检查与离线准备好的构建工具；wrapper 分发和依赖准备是独立动作，未运行的检查如实报告。

应用角色按实际证据区分；本语言模块可用于库、CLI、桌面或服务，框架问题另选专项。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
